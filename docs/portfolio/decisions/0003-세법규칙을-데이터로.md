# ADR 0003 — 세법 규칙을 코드가 아닌 데이터로 관리한다

- **상태**: 채택
- **일자**: 2026-08-28
- **관련**: [ADR 0004](0004-법령원문을-저장소에.md), [TS 0001](../troubleshooting/0001-종신연금-세율-오류.md)

## 맥락

계산 엔진에 들어가는 숫자는 대략 이렇다.

- 연령별 연금소득 원천징수세율 (5.5% / 4.4% / 3.3%)
- 이연퇴직소득 납부 비율 (70% / 60% / 50%)
- 사적연금 분리과세 기준금액 (연 1,500만 원)
- 연금수령한도 계산식의 상수 (11, 120%)
- 퇴직소득 근속연수공제·환산급여공제 구간표
- 기본세율 8구간과 누진공제액
- 연금소득공제 4구간, 한도 900만 원
- 건강보험 피부양자 소득·재산 기준 (2,000만 / 5.4억 / 9억)

**이 숫자들은 전부 매년 바뀔 수 있다.** 실제로 2026년에만 두 개가 바뀌었다.

가장 쉬운 구현은 코드에 그대로 쓰는 것이다.

```ts
const rate = age >= 80 ? 0.033 : age >= 70 ? 0.044 : 0.055  // 이렇게 하지 않는다
```

## 결정

**모든 세법 수치는 `src/lib/rules/<연도>.json` 에만 둔다.**
코드에 세율 리터럴이 등장하면 그것은 버그다.

```
src/lib/rules/2026.json   ← 지금
src/lib/rules/2027.json   ← 내년엔 이 파일만 추가
```

엔진은 `getRules(year)` 로 규칙을 주입받아 계산한다.

## 근거

**① 개정 대응 비용이 다르다**

코드에 박으면 개정 때마다 로직 파일을 뒤져야 하고, 어디를 놓쳤는지 확신할 수 없다.
데이터로 빼면 **바뀐 숫자만 교체**하면 되고, 코드는 건드리지 않으니 회귀 위험이 없다.

**② 과거 연도 재현이 공짜로 따라온다**

"2025년 기준으로 계산하면 얼마였나"를 별도 구현 없이 지원할 수 있다.
세법은 귀속 연도 기준으로 적용되므로 이건 실제로 필요한 기능이다.

**③ 근거 추적이 쉬워진다**

JSON의 각 항목에 `_ref` 필드로 명세서 조항 번호를 달아뒀다.
숫자 → 명세서 → 법령 조문 → `docs/sources/` 원문으로 추적된다.

## 결과

`2026.json` 구조 (발췌):

```json
{
  "pensionIncomeWithholding": {
    "_ref": "§5.1 / 소득세법 §129①5의2",
    "_note": "소득세율 5%/4%/3% + 개인지방소득세 10% = 원천징수세율",
    "byAgeDesc": [
      { "minAge": 80, "rate": 0.033 },
      { "minAge": 70, "rate": 0.044 },
      { "minAge": 55, "rate": 0.055 }
    ]
  }
}
```

## 이 결정이 실제로 회수된 사례

결정한 지 몇 시간 만에 효과가 증명됐다.

2차 자료를 근거로 종신연금 세율을 **4.4%로 잘못 입력**했다가, 법령 원문 확인 후 **3.3%** 임을 발견했다
([TS 0001](../troubleshooting/0001-종신연금-세율-오류.md)).

수정 범위는 이랬다.

| 파일 | 변경 |
|---|---|
| `rules/2026.json` | 값 1개 |
| `withdrawal.ts` | 조건식 1줄 (연령 상한 제거 — 법 개정으로 상한이 무의미해짐) |
| `tax.test.ts` | 기대값 갱신 |

**계산 로직 자체는 한 줄도 건드리지 않았다.** 세율을 코드에 박았다면 5.5%/4.4%/3.3%가 흩어진
분기문을 전부 찾아야 했을 것이다.
