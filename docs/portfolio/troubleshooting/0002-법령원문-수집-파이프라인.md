# TS 0002 — 법령 원문을 읽을 수 없던 문제

- **일자**: 2026-08-28
- **분류**: 데이터 수집
- **결과**: 미확인 규칙 5건 → 1건, 조문 원문 9건 확보

## 배경

[TS 0001](0001-종신연금-세율-오류.md)에서 2차 자료를 쓰면 안 된다는 결론이 났다.
그러면 법령 원문을 직접 읽어야 하는데, 이게 생각보다 막혔다.

## 시도 1 — 국가법령정보센터 웹페이지 ❌

```
https://www.law.go.kr/법령/소득세법/제129조
```

가져오면 **법령명만 있고 조문 내용이 없다.** 본문이 JavaScript로 렌더링되기 때문이다.

## 시도 2 — 법령 미러 사이트 ⚠️

정적 HTML로 조문을 제공하는 사이트를 찾아 조회했다. 조문은 읽혔지만 문제가 있었다.

- 시행일자가 **2025. 1. 1.** 기준 — 내가 필요한 건 2026년판
- 실제로 이 사이트는 종신연금을 **4%** 로 표시했다 (개정 전)

**하마터면 오류를 "검증했다"고 착각할 뻔했다.** 2차 자료의 문제는 틀린 게 아니라 **낡은 것**이다.

## 시도 3 — 인쇄용 URL 🔶

법령 사이트의 인쇄용 경로는 정적 HTML을 반환한다는 걸 발견했다.

```
https://www.law.go.kr/LSW//lsLawLinkInfo.do?...&print=print
```

조문이 읽혔고 시행일자도 2026. 1. 1.로 정확했다. 그런데 결정적인 벽이 있었다.

> **가목: "연금소득자의 나이에 따른 다음의 세율"**
> `<img src="http://www.law.go.kr/flDownload.do?flSeq=22186230" alt="img22186230">`

**나이별 세율표가 이미지 파일이었다.** 텍스트 대조가 불가능했다.

이 시점에 명세서에는 이렇게 적어뒀다.

> "국가법령정보센터는 제129조의 나이별 세율표를 이미지 파일로만 제공해 텍스트 대조가 불가능하다.
> 조문 원문 대조가 필요하면 법제처에서 법령 PDF를 내려받아 육안 확인해야 한다."

## 해결 — 법제처 OPEN API ✅

> "국세청, 법제처 등에서 제공하는 API가 있는지 확인해볼래?"

법제처가 **국가법령정보 공동활용 OPEN API**로 191개 API를 제공하고 있었다.
공개 예제 키(`OC=test`)로 바로 호출된다.

```bash
# 법령 검색 → 법령일련번호(MST) 획득
curl "https://www.law.go.kr/DRF/lawSearch.do?OC=test&target=law&type=JSON&query=소득세법"

# 조문 본문 조회 (JO = 조번호 4자리 + 가지번호 2자리)
curl "https://www.law.go.kr/DRF/lawService.do?OC=test&target=law&type=JSON&MST=280405&JO=012900"
```

응답은 **항 / 호 / 목 구조의 JSON**이었고, 결정적으로 이랬다.

```
가. 연금소득자의 나이에 따른 다음의 세율
   <img src="..." alt="img22186230" >
┌───────────┬─────┐
│나이(연금수령일 현재) │세율      │
├─────┬─────┼─────┤
│          │70세 미만 │100분의 5 │
├─────┼─────┼─────┤
│70세 이상 │80세 미만 │100분의 4 │
├─────┼─────┼─────┤
│80세 이상 │          │100분의 3 │
└─────┴─────┴─────┘
</img>
```

**웹에서 이미지로만 보이던 표를 API는 ASCII 아트로 함께 내려준다.**
`img` 태그 안쪽에 텍스트 표가 들어 있어서, 웹 렌더링에서는 보이지 않고 API 응답에만 남는다.

## 도구화

일회성 조회로 끝내지 않고 스크립트로 만들었다 — `scripts/fetch-law.mjs`

```bash
node scripts/fetch-law.mjs --law 소득세법 --jo 129 --save
node scripts/fetch-law.mjs --law "소득세법 시행령" --jo 40 --branch 2 --save
```

- 법령명으로 현행 법령의 MST를 자동 조회
- 항/호/목을 들여쓰기로 렌더링 (표는 ASCII 그대로 보존)
- `--save` 시 `docs/sources/` 에 **공포일·공포번호·시행일·요청 URL·취득일** 헤더와 함께 저장

## 성과

이 파이프라인으로 남아 있던 미확인 항목이 정리됐다.

| 항목 | 이전 | 이후 |
|---|---|---|
| 나이별 세율표 | 🔶 이미지라 대조 불가 | ✅ 원문 확인 |
| 연금외수령 세율 | ⚠️ 미확인 | ✅ §129①6나목 100분의 15 |
| 2013.3.1 이전 가입분 기산연차 | ⚠️ 추측(6년차설) | ✅ §40조의2④1호에 6년차 명시 |
| 인출순서 근거 조문 | §40조의4로 **오인** | ✅ §40조의3①로 정정 |
| 한도 초과분 처리 순서 | 구현은 했으나 근거 없음 | ✅ §40조의3③ "연금수령분이 먼저 인출" |

**미확인 5건 → 1건.** 남은 하나는 법령이 아니라 건강보험공단 확인이 필요한 사항이다.

## 배운 것

**"불가능하다"고 결론 내리기 전에 다른 접근 경로를 찾아야 한다.**

시도 3에서 "PDF 내려받아 육안 확인" 이라는, 자동화 불가능하고 재현도 안 되는 방법을 문서에 적었다.
그때 멈췄으면 이 프로젝트는 매년 세법 개정 때마다 사람이 눈으로 표를 읽어야 했을 것이다.

같은 데이터라도 **웹 페이지 / 인쇄용 페이지 / API가 각기 다른 형태로 제공**된다.
공공 데이터를 다룰 때는 기관이 API를 제공하는지 먼저 확인하는 게 순서다.
