# TS 0006 — 창이 안 줄어들어 iframe으로 모바일을 봤고, 그 과정에서 없는 버그를 만들었다

- **일자**: 2026-09-02

## 배경

Phase 1 설계 스펙 §7.4는 이렇게 정해 뒀다.

> 단위 테스트로는 레이아웃이 깨진 것을 잡지 못한다.
> 구현 후 Chrome으로 데스크톱·모바일 뷰포트 스크린샷과 콘솔 에러를 확인한다.

데스크톱은 바로 됐다. 문제는 모바일이었다.

## 증상 ① — 창 크기가 안 바뀐다

브라우저 자동화로 창을 390×844로 줄였다. 도구는 성공을 반환했다.

```
resize_window → "Successfully resized window ... to 400x880 pixels"
```

그런데 화면은 그대로였다. 확인해 보니

```js
{ inner: 1920, outer: 1918, dpr: 1 }
```

**창은 줄지 않았다.** 두 번 시도하고 그만뒀다.

## 해결 — 같은 문서 안에 작은 뷰포트를 만든다

미디어 쿼리는 **뷰포트 폭**을 본다. 그리고 `<iframe>` 은 자기만의 뷰포트를 갖는다.
그래서 페이지 안에 390px짜리 iframe을 띄우고 그 안에서 앱을 열었다.

```js
const f = document.createElement('iframe')
f.src = '/'
f.style.cssText = 'width:390px;height:640px'
document.body.appendChild(f)
```

같은 오리진이라 `localStorage` 로 입력값을 미리 심어 두고, `contentWindow` 로 스크롤까지 조작했다.
Tailwind 의 `sm:` 분기가 실제로 접히는 것을 눈으로 확인했다.

이 방식으로 잡은 것:

| 확인 | 결과 |
|---|---|
| 가로 스크롤 발생 여부 | `scrollWidth 375 ≤ innerWidth 390` — 없음 |
| 재원별 표 | 표 자체만 가로 스크롤(`scrollWidth 560`, 컨테이너 335) — 의도대로 |
| 슬라이더 눈금 | "1,500만" 라벨이 왼쪽으로 잘림 → 양 끝에서 정렬을 바꿔 수정 |
| 요약 2단 배치 | 390px에서 깨짐 → 세로로 쌓도록 수정 |
| **하단 고정 바** | **아예 없었다** — 스펙 §5.1 항목을 빠뜨린 것을 여기서 발견 |

마지막 항목이 이 검증의 값어치다. 테스트 77개가 전부 통과하고 있었지만
**만들지 않은 기능은 테스트가 잡아주지 않는다.**

## 증상 ② — 내가 만든 가짜 오류

콘솔을 확인하니 예외가 3건 있었다.

```
NotFoundError: Failed to execute 'removeChild' on 'Node':
The node to be removed is not a child of this node.
  at commitDeletionEffectsOnFiber (react-dom)
```

React 내부 스택이라 앱 버그처럼 보였다. 잠깐 원인을 찾을 뻔했다.

**원인은 나였다.** iframe을 붙이려고 이렇게 했다.

```js
document.body.innerHTML = ''
```

React가 관리하던 DOM 노드를 밖에서 전부 지웠고, 나중에 React가 그 노드를 정리하려다 실패한 것이다.
타임스탬프가 iframe을 심은 시각과 정확히 같았다.

콘솔을 비우고 새로 로드해 다시 확인했다.

```
read_console_messages (clear: true) → navigate → 입력 → 재확인
→ No console messages found
```

**오류·경고 0건.** 앱은 멀쩡했다.

## 재발 방지

- 검증 도구가 "성공"을 반환해도 **효과를 따로 확인한다.** `resize_window` 는 성공을 반환하고 아무것도 안 했다.
- **콘솔은 읽기 전에 비운다.** 이전 조작의 잔여물이 남는다.
- 페이지를 조작해 검증할 때는 **조작 자체가 만드는 오류**를 먼저 의심한다.

## 배운 것

브라우저 확인을 "스크린샷 한 장 찍고 끝"으로 생각했는데,
실제로 값어치가 나온 곳은 **스펙과 구현을 대조하는 순간**이었다.
하단 고정 바는 스펙에 한 줄로 적혀 있었고, 나는 그걸 빠뜨린 채로 테스트를 다 통과시켰다.

`docW ≤ innerW` 같은 **수치로 확인할 수 있는 것은 수치로 확인하는 게** 스크린샷을 눈으로 보는 것보다 확실했다.
가로 스크롤이 생겼는지는 눈으로 잘 안 보인다.
