# TS 0003 — 폴더명 대문자로 프로젝트 생성이 실패했다

- **일자**: 2026-08-28
- **분류**: 환경 설정
- **소요**: 약 5분

## 증상

기존 git 저장소 `C:\Project` 안에서 Next.js 프로젝트를 생성하려는데 실패했다.

```
Could not create a project called "Project" because of npm naming restrictions:
    * name can no longer contain capital letters
```

## 원인

`create-next-app`은 **대상 디렉터리 이름을 그대로 `package.json`의 `name` 필드**로 쓴다.
npm 패키지명 규칙은 대문자를 허용하지 않는다. 폴더명이 `Project`라서 걸렸다.

Windows에서 프로젝트 폴더를 대문자로 시작하는 건 흔한데, 이게 Node 생태계 규칙과 부딪힌 것이다.

## 검토한 선택지

| 안 | 문제 |
|---|---|
| 폴더명을 `project`로 변경 | git 저장소 경로가 바뀌고, 이미 열려 있는 도구들의 참조가 깨짐 |
| 하위 폴더에 생성 | 저장소 루트가 프로젝트 루트가 아니게 되어 배포 설정이 복잡해짐 |
| **임시 폴더에 생성 후 이식** | 부작용 없음 |

## 해결

소문자 이름으로 임시 폴더에 생성한 뒤, `.git`을 제외하고 내용만 옮겼다.

```bash
# 의존성 설치는 건너뛴다 — node_modules를 옮기는 건 느리고 의미도 없다
npx create-next-app@latest pension-plan --ts --tailwind --eslint --app \
    --src-dir --import-alias "@/*" --use-npm --skip-install --yes

rm -rf pension-plan/.git      # 새로 만들어진 저장소는 버리고
cp -r pension-plan/. /c/Project/   # 기존 저장소로 내용만 이식
```

`--skip-install`이 핵심이다. 설치까지 하고 옮기면 수만 개 파일을 복사하게 되는데,
Windows에서 이건 몇 분씩 걸린다. **뼈대만 옮기고 설치는 목적지에서 한 번 하면 된다.**

결과적으로 `package.json`의 `name`은 `pension-plan`이 되어 폴더명과 무관해졌다.

## 배운 것

작은 문제지만 **"도구가 요구하는 제약이 내 환경과 충돌할 때, 환경을 바꿀지 도구를 우회할지"**
판단이 필요했다. 여기서는 폴더명 변경의 파급이 더 컸으므로 도구를 우회하는 쪽을 골랐다.

`package.json`의 `name`은 npm에 배포할 게 아니면 폴더명과 일치할 필요가 없다.
제약이 실제로 무엇을 보호하는지 알면 우회해도 되는지 판단할 수 있다.
