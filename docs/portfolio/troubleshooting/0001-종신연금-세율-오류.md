# TS 0001 — 종신연금 세율이 틀렸다

- **일자**: 2026-08-28
- **분류**: 도메인 정확성
- **영향**: 종신연금 수령자의 세액이 실제보다 **33% 과다** 계산됨

## 증상

계산 엔진은 종신연금(사망할 때까지 받는 계약) 수령자에게 **4.4%** 세율을 적용하고 있었다.
테스트도 4.4%를 기대값으로 삼아 통과하고 있었으므로, 코드상으로는 아무 문제가 없어 보였다.

```ts
// 잘못된 기대값으로 통과하던 테스트
expect(pensionWithholdingRate(65, true, rules)).toBe(0.044)
```

## 발단

기능적 문제 제기가 아니라 **요구사항의 변화**에서 시작됐다.

> "세법조사를 하는데 이게 정확한 근거 데이터로 해야 되는데 정부나 국세청 등 근거가 정확히 필요한데"

명세서의 출처 목록을 다시 봤더니 이랬다.

- 증권사 연금 안내 페이지
- 회계법인 뉴스레터
- 개인 블로그 정리 글

**하나도 1차 출처가 아니었다.**

## 원인 추적

국세청 안내 페이지를 확인하자 바로 나왔다.

> "사망할 때까지 연금수령하는 종신계약에 따라 받는 연금: **3%** (2026.1.1. 이후 적용, 종전 4%)"

법제처 OPEN API로 조문 원문을 확인해 확정했다.

> **소득세법 제129조 제1항 제5호의2 다목**
> "다. 사망할 때까지 연금수령하는 대통령령으로 정하는 종신계약에 따라 받는 연금소득에 대해서는 **100분의 3**"
> — 공포 2025. 12. 23. 법률 제21221호 / 조문시행일자 2026. 1. 1.

**근본 원인**: 참고한 2차 자료가 **개정 전(2025년 이전) 기준**이었다.
같은 개정으로 이연퇴직소득 감면도 2단계(70%/60%)에서 3단계(70%/60%/50%)로 바뀌었는데,
그건 우연히 다른 자료에서 맞게 반영했다. **즉, 자료를 고른 운에 정확도가 좌우되고 있었다.**

## 해결

지방소득세 10%를 포함하면 3% → **3.3%** 다.

| 파일 | 변경 |
|---|---|
| `src/lib/rules/2026.json` | `lifetimeAnnuity.rate` `0.044` → `0.033` |
| `src/lib/tax/withdrawal.ts` | 연령 상한 조건(`age <= maxAge`) 제거 |
| `src/lib/tax/tax.test.ts` | 기대값 갱신 |

연령 상한을 뺀 이유가 있다. 종전에는 종신연금 4%가 나이별 세율(80세 이상 3%)보다 불리해지는
구간이 있어서 상한이 의미가 있었다. 개정 후 종신 세율이 3%가 되면서 **모든 연령에서 종신 세율이
같거나 낮아졌고**, 법은 "각 목의 요건을 동시에 충족하는 때에는 낮은 세율을 적용한다"고 정하므로
상한 조건 자체가 불필요해졌다.

```ts
// 각 목의 요건을 동시에 충족하면 낮은 세율을 적용한다 (소득세법 §129①5의2)
if (isLifetimeAnnuity && age >= life.minAge) {
  return Math.min(ageRate, life.rate)
}
```

**계산 로직은 한 줄도 바꾸지 않았다.** 세율을 데이터로 분리해 둔 덕분이다
([ADR 0003](../decisions/0003-세법규칙을-데이터로.md)).

## 재발 방지

오류 하나를 고치는 것으로 끝내면 같은 일이 반복된다. 세 가지를 바꿨다.

**① 출처 기준을 규칙으로 명문화** — `AGENTS.md` 규칙 4

> 근거로 쓸 수 있는 것은 법령 원문(국가법령정보센터)과 소관 기관(국세청·국민건강보험공단) 자료뿐이다.
> 증권사·언론·블로그는 근거가 될 수 없다.

**② 명세서에 검증 상태를 표기** — 모든 항목에 ✅ / 🔶 / ⚠️ 를 달았다.
확인 못 한 항목은 **추측으로 채우지 않고 ⚠️로 남긴다.** 지금 남은 ⚠️는 1건이다.

**③ 법령 원문을 저장소에 보관** — [ADR 0004](../decisions/0004-법령원문을-저장소에.md)

## 배운 것

**테스트가 통과한다고 맞는 게 아니다.**
30개 테스트가 전부 통과하고 있었지만, 기대값 자체가 틀린 근거에서 나왔기 때문에
테스트는 오류를 **고착시키는 역할**을 하고 있었다.

단위 테스트는 "구현이 의도대로인지"를 검증할 뿐 **"의도가 맞는지"는 검증하지 못한다.**
도메인 규칙을 다루는 프로젝트에서는 테스트 이전에 **근거의 신뢰도**를 관리해야 한다.

이 사건 이후 같은 방식으로 재점검하다가 **근거 조문 오인** 오류를 하나 더 발견했다
— 인출순서 근거를 시행령 §40조의4로 적었으나 실제로는 **§40조의3 제1항**이었다.
