# TS 0004 — 음수를 0으로 잘랐더니 1억 계좌에서 1.5억이 인출됐다

- **일자**: 2026-09-02
- **관련**: [ADR 0005](../decisions/0005-미지값을-범위로.md)

## 배경

연금계좌 잔액은 세 재원으로 나뉜다.

```
총잔액 = 과세제외금액 + 이연퇴직소득 + 세액공제분·운용수익
```

Phase 1 래퍼(`range.ts`)는 사용자가 준 **총잔액**과 **퇴직금 액수**에서 나머지를 역산한다.

```ts
taxable = totalBalance - taxFree - deferredSeverance
```

## 증상

이 뺄셈은 **음수가 될 수 있다.** 사용자가 총잔액 1억이라고 해놓고 퇴직금 3억을 받았다고
입력하면 `taxable = -2억` 이 된다.

음수 잔액은 말이 안 되므로 반사적으로 이렇게 썼다.

```ts
taxable: Math.max(0, input.totalBalance - taxFree - s.deferredSeverance)
```

## 원인

**이 방어 코드가 오히려 없는 돈을 만들어냈다.**

엔진은 인출 가능액을 세 재원의 **합**으로 잡는다 (`withdrawal.ts`).

```ts
const available = balance.taxFree + balance.deferredSeverance + balance.taxable
```

음수를 그대로 두면 합이 저절로 맞는다.

```
과세제외 2억 + 이연퇴직 0 + 과세대상 (-1억) = 1억  ← 사용자가 말한 총잔액
```

음수를 0으로 자르면 상쇄가 사라진다.

```
과세제외 2억 + 이연퇴직 0 + 과세대상 0 = 2억  ← 없는 1억이 생겼다
```

목표 인출액 1.5억으로 계산하면:

| | 인출액 | 부족분 |
|---|---|---|
| 클램프 없음 | 1억 | 5,000만 (경고 표시) |
| 클램프 있음 | **1.5억** | 0 |

**1억짜리 계좌에서 1.5억이 인출됐고, 그 세금까지 계산해서 보여줬다.**

## 어떻게 발견했나

발견한 게 아니라 **TDD 절차가 잡아냈다.**

클램프는 테스트 없이 "혹시 모르니까" 넣은 코드였다. 나중에 이걸 알아채고
규칙대로 되돌려서 RED를 확인하려 했는데 — **테스트 61개가 전부 통과했다.**

테스트가 통과했다는 건 그 코드가 아무것도 하지 않는다는 뜻이었다.
그래서 클램프를 실제로 가르는 입력을 찾다가, 과세제외금액이 총잔액보다 큰 경우에서
방향이 반대라는 걸 알았다. 방어가 아니라 버그였다.

## 해결

클램프를 제거하고, **재도입을 막는 회귀 테스트**를 넣었다.

```ts
it('재원 합계가 총잔액을 넘어도 총잔액보다 많이 인출되지 않는다', () => {
  // 과세제외금액 2억 > 총잔액 1억, 목표 인출 1.5억
  const r = calculateWithdrawalRange(overstated, YEAR)
  expect(r.representative.withdrawnAmount).toBe(100_000_000)
  expect(r.representative.shortfall).toBe(50_000_000)
})
```

클램프를 되살려 이 테스트가 `expected 150000000 to be 100000000` 으로 실패하는 것을
확인한 뒤 다시 제거했다. **테스트가 실제로 무언가를 가른다는 것을 눈으로 본 다음** 통과시켰다.

## 재발 방지

- **테스트 없이 방어 코드를 넣지 않는다.** 검증되지 않은 방어는 방어인지 버그인지 알 수 없다.
- 되돌렸는데 테스트가 다 통과하면 **그 코드는 죽었거나 테스트가 무르다.** 둘 중 하나를 고친다.
- 재원 합계는 엔진의 계약이다. 래퍼가 재원별 값을 조작할 때 **합이 총잔액과 같아야 한다**는
  불변식을 깨면 안 된다.

## 배운 것

`Math.max(0, x)` 는 습관처럼 쓰게 되는 코드다. 값 하나만 보면 "음수 방지"가 맞다.
그런데 이 값은 혼자 쓰이는 게 아니라 **다른 두 값과 합쳐져 의미를 만든다.**
합에 참여하는 항을 단독으로 보정하면 합이 깨진다.

Phase 0에서 배운 것이 "근거를 확인하고 쓰라"였다면, 이번에 배운 것은
**"방어 코드도 근거가 필요하다"** 이다. 어떤 입력에서 무엇을 막는지 말할 수 없다면
그건 방어가 아니라 추측이다.
